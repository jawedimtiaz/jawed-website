Building Small IT Automations: Start With the Repetitive Step

A practical way to identify small, low-risk automation opportunities by starting with repetitive work and keeping the first version simple.

2026-09-27

Find the repetitive step

Good automation candidates are often small tasks that are repeated frequently and follow a predictable process. Start with the step that consumes time rather than trying to automate an entire workflow at once.

  • Repeated formatting or data preparation
  • Consistent ticket or documentation structure
  • Routine checks with clear inputs and outputs
  • Copy-and-paste work between systems

Define the input and output

Before writing anything, describe what goes in and what should come out. A clear boundary makes a small automation easier to test and safer to change.

For example: Input → transformation → output. Keep the first version focused on one predictable task.

Keep the first version reversible

A useful first automation should be easy to test and easy to stop using. Avoid making irreversible changes until the process is well understood.

  • Prefer generated output over automatic destructive changes.
  • Keep the original information available.
  • Test with sample data first.
  • Make failures visible rather than silently ignoring them.

Validate against the manual process

Compare the automated result with a manually completed example. Check accuracy before measuring how much time the automation saves.

  • Correctness
  • Consistency
  • Edge cases
  • Ease of recovery

Improve only after it works

Once the small version is reliable, decide whether it should handle more cases. This keeps automation maintainable and prevents a simple task from becoming an unnecessarily complex project.

Small, reliable improvements can often deliver more practical value than a large automation that is difficult to understand or maintain.
