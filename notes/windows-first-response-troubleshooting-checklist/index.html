Windows First-Response Troubleshooting Checklist

A practical first-response checklist for common Windows support cases before moving to deeper investigation or escalation.

2026-09-27

1. Understand the symptom

Ask what the user was trying to accomplish, what happened instead and when the problem started. Capture exact error messages and whether the behavior is repeatable.

2. Check the basic device state

  • Confirm the device is powered on, responsive and connected as expected.
  • Check network connectivity and whether other services work.
  • Check available storage when the issue involves updates, applications or general system behavior.
  • Confirm the expected user account and sign-in state.

3. Determine the scope

Work out whether the issue follows the user, the device or the service. Where appropriate and permitted, compare with a known-good device or account instead of changing several variables at once.

4. Check recent changes

Ask whether the issue started after a restart, update, application change, network change or other relevant event. Recent changes can provide useful evidence without assuming they caused the problem.

5. Apply the least disruptive supported fix

Prefer documented and reversible troubleshooting steps. Avoid disabling security controls, removing management components or deleting system data simply to make a symptom disappear.

6. Validate the original task

After a change, have the user repeat the task that originally failed. Confirm the expected application, service or device function works before closing the issue.

7. Document and escalate when needed

Record the symptom, evidence, checks, changes and result. If another team needs to continue the investigation, provide the current state and useful evidence rather than only reporting that the issue persists.
