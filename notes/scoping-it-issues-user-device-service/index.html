User, Device or Service? A Simple Way to Scope IT Issues

A simple framework for deciding whether an IT problem is primarily associated with a user, a device or a shared service before deeper troubleshooting.

2026-09-27

Why scope matters

The same symptom can have very different causes. Identifying the likely scope early helps avoid unnecessary changes and gives you a clearer troubleshooting path.

Start by asking whether the problem follows the user, the device or the service.

If it looks user-specific

Consider whether the issue follows the person's account, permissions, profile or workflow. Where policy allows, a controlled comparison can help distinguish a user-specific problem from a wider service issue.

  • Does the same user experience the issue elsewhere?
  • Does another user work normally on the same device or service?
  • Is the problem tied to one account or workflow?

If it looks device-specific

If the issue remains with one device while the same user or service works elsewhere, investigate the device state and configuration.

  • Is the device connected and responsive?
  • Does the issue occur across relevant applications?
  • Does a known-good comparison point to the device?

If it looks service-wide

When multiple users or devices experience the same behavior, consider a shared service or infrastructure issue before changing individual devices.

  • Are multiple users affected?
  • Did the problem begin around the same time?
  • Is there an existing service or incident notification?

Use scope to guide the next test

Scoping is not the final diagnosis. It is a way to choose the next useful test while avoiding unnecessary changes.

After each test, update your working hypothesis and document what the result tells you. If the evidence points outside your support scope, escalate with that evidence.
